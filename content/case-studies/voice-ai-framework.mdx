# Voice AI Framework

**Outcome:** Sub-500ms overall turn latency on a high-concurrency telephony path.

Healthcare and recruitment workflows needed agents that book appointments, run prior-auth conversations, and interview candidates—without sounding like IVR and without blowing a half-second response budget.

## Problem

Voice turns fail when the pipeline stacks STT wait + LLM TTFT + TTS first-byte + network. Barge-in (interruptibility) makes the problem harder: the system must cancel in-flight TTS, retain context, and resume without dumping tool state. The domain is regulated (HIPAA boundary on transcripts and tool payloads), so logging and vendor boundaries matter as much as model quality.

## Approach

I designed a reusable **Voice AI Agent Framework** and shipped specialized agents on top of it:

- **Appointment Scheduler** — slot search, confirm, reschedule via tool-calls
- **Prior Auth Agent** — structured intake and payer workflow turns
- **Interviewer Agent** — scripted + adaptive question loops for recruiting

Core loop: **Deepgram STT → LLM (Azure OpenAI and/or local vLLM) → ElevenLabs TTS**, with Twilio as the telephony edge. Inference workers run on **AWS EC2 in Docker**, with worker pools sized for concurrent calls. Domain adaptation: fine-tuned **Qwen 3** on **1.2K call transcripts** to raise tool-calling and information-extraction accuracy.

## What I built

- Designed the agent runtime: turn state, interruptibility, and tool-use contracts for scheduling and intake
- Containerized **vLLM** workers on **AWS EC2**; instrumented concurrency and cold-start behavior
- Wired a **HIPAA-oriented STT–LLM–TTS** path (Deepgram, Azure OpenAI, ElevenLabs) with careful PHI handling at log boundaries
- Fine-tuned **Qwen 3** on 1.2K transcripts; measured lift on tool-call success and field extraction
- Deployed Appointment / Prior Auth / Interviewer agents on the shared framework

## Engineering notes

1. **Barge-in vs latency:** Cancelling TTS early saves perceived lag but races tool execution; I kept tool commits idempotent so a partial utterance cannot double-book.
2. **Cloud LLM vs vLLM:** Azure OpenAI for capability; local vLLM when TTFT and cost under concurrency dominate. The framework treats both as swappable backends behind one turn API.
3. **Fine-tune vs prompting:** Prompt-only tool schemas drifted on healthcare jargon; the 1.2K-transcript Qwen adapt reduced malformed tool calls more than longer system prompts alone.
