# Multi-Agent Project Manager

**Outcome:** An orchestration stack that turns project goals into prioritized tasks, staffing suggestions, and actionable reports—without a single monolithic prompt.

Reframe: this is not a “project management SaaS pitch.” It is a **planning + orchestration** demo—agent roles, tool interfaces, and retrieval context working as a graph.

## Problem

Single-agent PM chatbots collapse under long context: task generation, prioritization, team fit, and reporting fight for the same window. Failures show up as hallucinated deadlines, staffing that ignores skills, and reports that ignore earlier decisions. The hard problem is **role separation + shared memory + tool contracts**, not another dashboard skin.

## Approach

I built a multi-agent system where specialized agents own one job and hand off structured artifacts:

- **Task generation** from goals and constraints
- **Prioritization** with context-aware suggestions
- **Team configuration** for optimal staffing mixes
- **Report generation** with actionable insights

Retrieval: **FAISS + RAG** so agents ground suggestions in project docs rather than inventing scope. Inference via **GROQ**; orchestration with **LangChain**-style agent loops (extendable toward LangGraph topologies used in production work).

## System

```
                    ┌─────────────┐
   Project docs ──► │ FAISS / RAG │
                    └──────┬──────┘
                           │ retrieved chunks
                           ▼
                 ┌───────────────────┐
                 │  Orchestrator     │
                 └─────────┬─────────┘
       ┌─────────┬─────────┼─────────┬─────────┐
       ▼         ▼         ▼         ▼         ▼
   Planner   Prioritizer  Staffer  Reporter  (tools)
       │         │         │         │
       └─────────┴────┬────┴─────────┘
                      ▼
              Shared task / plan state
```

**Suggested artifact:** agent graph SVG — nodes = agents, edges = tool/artifact handoffs; highlight retrieval edges into FAISS.

## What I built

- Designed agent roles and the shared plan/task schema each handoff must satisfy
- Wired **RAG over FAISS** for context-aware tasking and suggestions
- Implemented prioritization and team-configuration agents so staffing is a separate decision from task dump
- Built dynamic **report generation** that summarizes decisions into actionable insights
- Shipped the system as a public GitHub project for inspection and extension

## Engineering notes

1. **Split agents beat mega-prompts:** Prioritization quality improved when the planner could not also rewrite staffing mid-turn.
2. **RAG is a contract:** Chunking and metadata (epic, owner, due date) matter more than model size for “context-aware” claims.
3. **What I’d do next:** Migrate the graph to **LangGraph** with explicit checkpoints, add an eval harness (golden plans: task completeness, priority agreement, staffing constraint violations), and expose traces (Phoenix/LangSmith) as a portfolio observability screenshot.
